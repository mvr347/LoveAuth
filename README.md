# LoveAuth

Система аутентификации и авторизации для Paper сервера с хешированием Argon2, проверкой лицензии Mojang и управлением сессиями.

## Общая структура

LoveAuth предоставляет защищённую систему входа/регистрации для некрэка (offline mode) и Premium-серверов. Поддерживает криптографическую проверку лицензии через хендшейк Mojang (Yggdrasil), хранение паролей через Argon2id с pepper, шифрование данных через AES-256-GCM, управление сессиями с привязкой по IP-адресу и кулдауны на повторный вход.

## Команды

| Команда | Алиасы | Описание |
|---|---|---|
| `/loveauth` | `auth`, `авторизация`, `регистрация`, `вход` | Главная команда авторизации |
| `/loveauthadmin` | `ладмин` | Панель администратора LoveAuth (пермишин: `loveauth.admin`) |
| `/ladmin` | — | Устаревшее имя `/loveauthadmin`, оставлено как редирект с подсказкой |

### Подкоманды `/loveauth`

- `register <пароль>` — зарегистрировать новый аккаунт с паролем
- `login <пароль>` — войти в аккаунт с паролем
- `logout` — выйти (завершить сессию)
- `changepassword <старый> <новый>` — изменить пароль

### Подкоманды `/loveauthadmin`

- `reload` — перезагрузить config.yml и языковые файлы
- `unlock <player>` — разблокировать аккаунт игрока
- `unblockip <ip>` — разблокировать IP-адрес
- `info <player>` — подробная информация об игроке и его альтах
- `session reset <player>` — сбросить сессию игрока
- `setadminpass` — установить admin-пароль
- `delete <player>` — удалить все данные игрока
- `setfirstspawn` — установить точную точку первого спавна (для `register-spawn`) в текущей позиции админа
- `amnesty` — снять все блокировки IP и аккаунтов

## Меню

Все меню собраны по gui_gen v2.1. Кнопки всегда стоят по центру рабочей строки, даже если часть из них скрыта настройками: регистрация без Discord показывает одну кнопку по центру, приветствие лицензионного игрока — две, а `/loveauth account` — сетка 3×2 (36 слотов) из шести постоянных кнопок. Недоступная кнопка остаётся на месте серой, с одной красной строкой причины.

Оформление текста меню лежит в секции `gui` файла `lang/lang.yml` и защищено `lang-version`: при обновлении плагина секция `gui` перезаписывается из поставки, а прежний файл сохраняется рядом как `lang.yml.bak-vN`. Остальные секции (сообщения, префикс) не затрагиваются.

## Конфигурация (`config.yml`)

### База данных

```yaml
database:
  file: "loveauth.db"  # файл SQLite
```

### Безопасность

```yaml
security:
  # Pepper добавляется к паролю перед хешированием (генерируется автоматически)
  pepper: ""
  # AES-256-GCM ключ для шифрования чувствительных данных (генерируется автоматически)
  master-key: ""
  # Параметры Argon2id
  argon2-iterations: 10              # 10-14 рекомендуется
  argon2-memory-kb: 65536            # 64 МБ
  argon2-parallelism: 1              # 1 для большинства серверов
```

### Сессии

```yaml
session:
  enabled: true                      # включить сессии (можно заходить без пароля)
  duration-days: 7                   # длительность сессии в днях (1-28)
  bind-to-ip: true                   # сбрасывать сессию при смене IP
```

### Авторизация

```yaml
auth:
  timeout-seconds: 90                # максимум 90 секунд на вход/регистрацию
  max-attempts: 3                    # максимум неверных попыток пароля
  lockout-duration-minutes: 60       # блокировка IP на 60 минут после исчерпания попыток
  min-password-length: 6             # минимальная длина пароля
  admin-max-attempts: 5              # попытки для /loveauthadmin
  admin-lockout-duration-minutes: 15 # блокировка admin-команд на 15 минут
  premium-skip: true                 # пропускать авторизацию для лицензионных игроков
```

### Протокольная проверка лицензии (Yggdrasil/Mojang)

```yaml
premium-verification:
  enabled: true                      # включить криптографическую проверку лицензии
  timeout-ms: 5000                   # ждать ответа 5 сек на каждом шаге хендшейка
  block-cracked-licensed-accounts: true  # блокировать крэк-вход под ником зарегистрированного лицензионника
```

## Механика входа

1. **Новый игрок** → `/loveauth register <пароль>` → создание аккаунта
2. **Лицензионный игрок** → если `premium-skip: true`, пропускается авторизация (проверяется по хендшейку Mojang)
3. **Возвращающийся игрок** → `/loveauth login <пароль>` → проверка пароля
4. **Если включены сессии** → можно заходить без пароля до истечения срока сессии (по умолчанию 7 дней)
5. **Если изменился IP** → при `bind-to-ip: true` сессия сбрасывается и требуется повторная авторизация

## Безопасность

- **Argon2id хеширование** — стойко к GPU-атакам, параметры (iterations, memory) настраиваются
- **Pepper** — секретная добавка к паролю, генерируется один раз, не меняется
- **AES-256-GCM шифрование** — для чувствительных данных в БД
- **Проверка лицензии Mojang** — криптографический хендшейк для подтверждения Premium-статуса
- **IP-привязка сессий** — защита от кражи сессии при смене IP
- **Кулдауны и блокировки** — защита от brute-force атак на пароли и admin-команды

## Структура данных

- `accounts` — аккаунты игроков (ник, хеш пароля, дата создания, последний вход)
- `sessions` — активные сессии (игрок, IP, срок действия)
- `lockouts` — временные блокировки IP (IP, дата истечения)
- `audit_log` — логи попыток входа для безопасности

## Технические детали

- Хеширование паролей: **Argon2id** (стойко к GPU-ускорению)
- Шифрование данных: **AES-256-GCM** (authenticated encryption)
- Проверка Premium: **Yggdrasil handshake** (оригинальный протокол Mojang)
- Хранилище: **SQLite** с HikariCP connection pool

## Последние улучшения (v1.5+)

### Безопасность и надёжность

- **Null-safety в getIp():** Защита от NPE при отсутствии адреса сокета
- **Timeout защита:** Ограничение времени ожидания (15 сек) для асинхронных операций БД в PlayerLoginListener
- **Race condition fix:** Синхронизация shutdown() с DatabaseManager для предотвращения исключений при отключении
- **Localization coverage:** Добавлены все недостающие ключи в lang.yml (12+ ключей для логирования, GUI и ошибок)

### Оптимизация и cleanup

- **Удаление мёртвого кода:** Исключен неиспользуемый pendingAdminActions map
- **Логирование ошибок:** Добавлено логирование в previousу-безмолвные catch-блоки (Discord DM failures, malformed button IDs)
- **Graceful shutdown:** Улучшена обработка отключения Netty handlers при перезагрузке

### Обработка сетевых ошибок

- **Timeout handling:** ReadTimeoutException и IOException при хендшейке обрабатываются без error-логов (как ожидаемое поведение)
- **Netty pipeline stability:** Добавлена зависимость netty-handler для compile-time проверки типов исключений

## Восстановление состояния после limbo

При разморозке игрока с исходным режимом `SURVIVAL` LoveAuth снимает ванильный флаг
`isInvulnerable`, даже если он был ошибочно установлен до авторизации. Это не позволяет
повторно сохранять застрявшую неуязвимость после выхода. Для остальных режимов флаг
восстанавливается из снимка; скорости, полёт и невидимость восстанавливаются как прежде.
Один снимок применяется только один раз; повторный вызов разморозки не меняет состояние.


### Единое оформление Love

Префикс сообщений использует тематическое русское название в градиенте из двух цветов и белый разделитель `»`. Команды, права и плейсхолдеры сохраняются.

Для обновления существующих конфигов установите актуальный LoveCore вместе с этой версией.
Однократная миграция сохраняет исходные YAML рядом с ними как `.pre-style-20261101.bak`.
После обновления можно менять оформление самостоятельно: перезапуск его не сбрасывает.

### Общий кабинет Discord

Авторизация использует Discord-транспорт LoveCore и больше не запускает второй шлюз JDA.
Сначала обновите LoveCore, настройте в нём токен и сервер бота, затем установите эту версию
LoveAuth. Если токен ядра пуст, настройки старого бота переносятся с резервной копией
`config.yml.pre-shared-discord.bak`; существующий токен ядра не перезаписывается.

`/меню` в личных сообщениях бота объединяет аккаунт, безопасность и обращения LoveWebAdmin.
Подтверждения входа, блокировки, отвязки и смены пароля — отдельные сообщения с одноразовыми
кнопками. Они проверяют владельца, сообщение, срок, а для входа — текущий IP и актуальность
подключения. Старая карточка смены пароля не может применить хеш нового запроса.
Пароль вводится дважды в закрытой форме; при остановке ожидающие запросы отменяются.

### Уведомление о входе и временные сообщения

Запрос Discord-входа снова использует карточку «🔐 Запрос на вход» из lang.yml:
«Игрок … пытается войти на сервер. Это вы?». Подтверждение зелёное, отказ красный,
переходы синие. В игре снова показывается уведомление об отправленном запросе.

Запрос остаётся доступен до ответа или истечения срока. После ответа результат показывается
две секунды и сообщение бота удаляется. При выходе игрока или новом запросе старое
ожидание удаляется сразу; запоздавший ответ транспорта также очищается. Навигационная
карточка кабинета остаётся. Срок отсчитывается после завершения обновления сообщения;
недоступность Discord может помешать фактическому удалению. Нужен совместимый LoveCore
с методом удаления собственного DM. Все проверки владельца, nonce, IP и поколения входа сохранены.

Для личного раздела диагностики входа добавлен read-only метод `DiscordAuthManager.getDiscordLoginStatus(discordOwner)`. Он ищет запись только по владельцу Discord и возвращает минимальный статус привязки/блокировки/авторизации/подтверждения. Состояние Bukkit читается через существующий диспетчер главного потока. IP, пароли, хэши, коды и данные сессий не выдаются; ожидающее подтверждение не применяется автоматически.

### Обновление 04.11.2026: карточка безопасности

### Библиотеки сервера (05.11.2026)

SQLite JDBC 3.50.3.0 загружается штатным механизмом `libraries` Paper и больше не встраивается в JAR. При первом запуске серверу нужен доступ к Maven Central; затем используется локальный каталог `libraries`. Сохраняйте этот каталог для запуска без сети. Перенос на новый сервер без сети требует переноса и кэша библиотек. Нативные компоненты Windows/Linux не вырезаются и пакеты `org.sqlite` не переименовываются. Публичное API плагина не меняется.

LoveAuth использует общий бот LoveCore; неиспользуемый транспорт JDA и его зависимости удалены из сборки. Команды, привязка, подтверждение входа и публичные методы DiscordAuthManager сохранены. При перезагрузке вновь разрешаются запросы основного потока, старые результаты прогрева кэша не переходят в новую сессию модуля. Повторная выдача кода одному игроку возвращает действующий код; хранилище ограничено, срок — 10 минут, на каждое нажатие не создаётся новая задача Bukkit.
